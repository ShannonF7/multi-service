# Stage 29 审计：节点属性查询与负责人答案

## 用户问题

用户先问位置，再问“管理员是谁”。系统应：

1. 将短问题识别为属性事实问题，而不是位置问题。
2. 承接上一轮已确认节点。
3. 查询该节点的已发布事实和关系。
4. 有负责人属性时返回属性值和引用。
5. 确实没有属性时才提示未记录。

## 根因

本轮发现两个问题：

1. 早期链路把“管理员是谁”错误复用为 LOCATION 快速答案。
2. 图谱证据转换中使用了 `formal_property_id` 优先级：
   `99：贾鹏`
   
   这覆盖了真实属性名“创建者与负责人”，导致属性答案判断无法识别“负责人”，并错误进入缺失属性分支。

## 修改

### graph_adapters.py

事实证据现在优先使用：

```
fact.key
→ formal_property_id 仅作为无名称时的兜底
```

因此证据变为：

```
创建者与负责人：贾鹏
```

同时事实证据 ID 使用可读属性名：

```
graph:4:1665:fact:创建者与负责人
```

### answering.py

新增 `fast_attribute_answer`：

- 从 `Evidence.metadata.fact` 读取属性键和值。
- 支持管理员、负责人、联系人、电话、邮箱、名称。
- 直接生成简短答案和引用。
- 不调用答案模型，避免无意义等待。

### service.py / streaming.py

同步问答和 SSE 问答统一使用：

```
fast_graph_answer
→ fast_attribute_answer
→ fast_attribute_unavailable_answer
→ Qwen答案生成
```
