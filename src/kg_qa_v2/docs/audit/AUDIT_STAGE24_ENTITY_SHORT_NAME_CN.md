# Stage 24 实体短名称召回修复审计

## 目标

修复“智能光学实验室在哪里？”没有进入已发布图谱检索、最终返回无证据的问题。

## 修改与输入输出

- 修改 slots.py：Qwen 槽位输出为空时，对知识问题启用确定性目标抽取兜底。
- 输入：问题、Router 结果、Qwen 槽位 JSON、当前领域与会话上下文。
- 输出：包含 targets 和 entity_refs 的 QuerySpec，source 标记为 jev+qwen+fallback。
- 后续由 PublishedCandidateSearch 调用当前领域的已发布图谱候选搜索。

## 根因

Qwen 返回合法但空的 JSON 时，旧代码直接认为槽位抽取成功，导致实体候选搜索不执行，图谱节点没有对齐 ID，最后以已完成状态返回无证据答案。

## 修复边界

- 仅 KNOWLEDGE 路由且没有实体引用时启用。
- 规则抽取不到目标时不凭空制造实体。
- 闲聊和当前位置问题不受影响。
- 仍只访问已发布图谱，不新增自由 Cypher。
- 不直接使用尚未证明只包含已发布节点的向量索引。

## 测试

- 新增回归测试：2 passed。
- QA v2 全量测试：92 passed。
- 既有警告：1 个 Pydantic class-based config 弃用警告，与本次修改无关。

## 审计结论

空槽位不再静默吞掉用户的实体名称。智能光学实验室这类简称会进入当前领域已发布图谱的候选召回，再依据层级、领域和对齐置信度决定回答或澄清。
