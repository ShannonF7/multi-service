# QA v2 阶段 20：实体引用、层级召回与实体对齐审计

审计时间：2026-10-05
审计范围：src/kg_qa_v2/contracts.py、entity_reference.py、slots.py、entity.py、pipeline.py、阶段 20 测试
审计目标：修复“用户没有使用完整节点名称时直接判定无实体”、多级定语导致召回失败、上下文代词重新搜索、当前位置被当作实体搜索等问题。

## 一、输入与输出

### 1. EntityReference

输入：

- 用户原问题；
- 槽位抽取出的 targets；
- 当前领域和会话上下文；
- 当前问题意图及 needs_current_location。

输出：

- surface：用户原始提法；
- core_mention：去掉领域、校区、楼座、楼层等定语后的核心名称；
- qualifiers：结构化的层级、区域、组织、地理定语；
- reference_type：EXPLICIT、CONTEXTUAL、CURRENT_LOCATION、UNKNOWN；
- resolved_node_id：上下文中已经确认的节点 ID（若存在）。

示例：

太原理工大学明向校区行政楼B座财务部

会形成：

- 核心名称：财务部
- 层级定语：太原理工大学、明向校区、行政楼、B座

### 2. Candidate Search

输入：

- 核心名称；
- EntityReference；
- 当前领域上下文。

处理：

1. 使用完整表述、核心名称、结构化定语生成多个召回词；
2. 每个召回词都调用已发布图谱 gateway；
3. 合并相同 node_id；
4. 统一 score 和旧服务返回的 match_score；
5. 按名称、别名、核心名称、反向包含、层级路径重新标注匹配类型；
6. 根据候选的层级路径命中情况加权。

输出：

- 领域内已发布候选；
- node_id、名称、别名、层级路径；
- match_type；
- 0~1 的可比较分数；
- 实际命中的召回词和层级命中数量（放入 metadata，便于审计）。

### 3. Entity Alignment

输入：

- 候选列表；
- 当前领域；
- 当前节点和位置；
- 用户问题。

输出：

- LINKED：可以安全使用；
- AMBIGUOUS：候选仍然有歧义，转澄清；
- UNRESOLVED：没有可用候选。

对齐不会创造节点，也不会跨领域选节点。多个同名节点只有在层级证据造成足够分差时才自动选择，否则仍然澄清。

## 二、关键逻辑审计结论

### 已修复

1. 不再只用用户完整提法作为一次查询。
2. “山西张壁古堡”会额外召回“张壁古堡”。
3. “太原理工大学明向校区的校长办公室”会提取“校长办公室”作为核心名称。
4. “行政楼B座二楼财务部”可以利用行政楼、B座、二楼/二层的路径证据区分同名节点。
5. “它/这个/那个/该楼”等上下文代词优先读取会话中的最近实体；若上下文中已有当前节点 ID，则跳过候选搜索。
6. “我现在在哪里/当前位置在哪里”生成 CURRENT_LOCATION 引用，不会再把“我现在”作为实体名搜索。
7. 图谱旧服务返回 0~100 的 match_score 时，QA v2 会转换为 0~1；否则旧结果会因为 EntityCandidate.score 默认值为 0 而失去对齐依据。
8. 生产候选搜索仍然携带 domain_id 和 published_only=True，本阶段没有放开跨领域或未发布数据。

### 仍然保持的安全边界

- 不修改旧的图谱发现服务；
- 不生成自由 Cypher；
- 不把描述、事实命中直接当成强身份；
- 不因“只有一个低质量候选”而强行绑定；
- 不让答案生成模型重新决定实体或检索范围。

## 四、审计发现与后续边界

本阶段的多召回是建立在现有“已发布图谱 gateway”之上的适配层，已经解决了名称前缀、完整定语、反向包含和层级路径评分问题；但尚未新增独立的实体别名索引、字符级模糊索引或向量实体索引。若现有图谱查询对某个核心名称完全没有返回候选，当前适配层也无法凭空恢复该节点。

因此下一阶段应使用真实领域数据评估：

- recall@1、recall@3、recall@5；
- 简称、别名、错别字和口语化名称的召回率；
- 同名节点的误绑定率；
- 代词连续追问的正确率；
- 当前领域隔离和已发布过滤的正确率。

本阶段结论：实体引用解析和基于现有已发布图谱的多词召回已经接入 QA v2，并通过单测和全量回归；独立别名/向量索引属于后续索引建设，不在本次改动中伪装成已完成。
