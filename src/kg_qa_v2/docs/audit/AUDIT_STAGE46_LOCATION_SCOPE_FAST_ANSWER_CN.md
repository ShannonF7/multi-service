# Stage46 审计：领域定位范围与简单问答直答

## 本阶段目标

1. 当前定位问题必须先判断用户是否在当前已发布领域范围内，不能因为领域内存在某个最近节点就直接把它当成用户位置。
2. 当前定位不能回退到上一轮会话的 active entity。
3. 已完成节点对齐的简单位置/外观问题，优先使用图谱层级和节点已发布图片，避免再次调用答案生成模型。

## 实现审计

### 1. 领域范围

- `resolve_published_domain_scope()` 从当前领域的已发布节点坐标计算中心和范围。
- 优先使用带坐标的顶层节点；没有顶层坐标时使用带坐标节点的中位数，避免平均值被离群坐标拉偏。
- 默认半径为坐标距离分布 P95 加缓冲，最终限制在 300～5000 米；不是针对张壁古堡写死的坐标或名称规则。
- 可以用 `KG_QA_DOMAIN_SCOPE_RADIUS_M` 明确覆盖某个部署环境的默认半径；可以用 `KG_QA_DOMAIN_SCOPE_MARGIN_M` 调整自动范围缓冲。
- 当前张壁古堡领域实际计算结果：中心约为 `36.96195, 111.97326`，半径约 `390.82m`，使用 90 个已发布坐标点，来源为 `published_coordinates_p95`。

### 2. GPS 到领域节点

- GPS 在范围外时，`current_location` 保留坐标和范围判断，但不设置 `node_id/name`，也不调用最近节点绑定。
- GPS 在范围内时，才在当前领域已发布节点中查找最近节点。
- `current_location` 图谱操作只接受本次定位得到的 `location_node_id`，不再使用上一轮的 `current_node_id`。
- 范围外会生成受限证据：“你当前不在……的范围内”，不会生成具体景点名称。

### 3. 简单视觉位置问题

- Router 命中 `fast_path` 后，短问题使用本地结构化兜底解析，不再调用慢槽位模型。
- `VISUAL_APPEARANCE/IMAGE_RETRIEVAL` 已经有已对齐节点时，直接读取节点绑定的已发布图片。
- 当问题同时包含“在哪里”和“长啥样”时，节点绑定图片不再做无必要的二次重排；单独的视觉图片问题仍保留图片重排能力。
- 图谱位置与图片证据满足条件时，答案使用确定性模板输出，SSE 直接发送 token，不调用答案 API。

## 输入、输出与副作用

- 输入：领域 ID、用户 GPS、会话上下文、QuerySpec、已发布节点/图片。
- 输出：`location_in_domain`、领域中心、半径、距离、最近节点（仅范围内）、图谱/图片 Evidence。
- 不修改 Neo4j 图谱、不写入节点、不改变用户 GPS；只影响本轮问答上下文和答案计划。
- 证据仍沿用现有 `Evidence` 和引用校验链路，确定性答案不会绕过引用绑定。

## 已知边界

当前 `KnowledgeDomain` 没有统一中心坐标字段，所以自动范围是“已发布坐标点推导范围”。如果某领域存在大量错误坐标，管理员应通过 `KG_QA_DOMAIN_SCOPE_RADIUS_M` 覆盖默认半径；下一阶段可在领域配置中显式维护中心点和半径。
