# Stage 17：闲聊延迟与 SSE 首包热修复审计

## 问题定位

此前“你好”请求在约 25 秒后才出现答案，时间主要消耗在：

- 本地 7B 路由模型调用；
- 闲聊后仍继续调用结构化槽位模型；
- pipeline 以同步方式执行，阶段事件只能在 pipeline 返回后集中发送；
- A 端丢弃 started 事件，页面持续显示“正在准备回答”；
- 闲聊答案仍进入引用校验，模型偶尔输出 E 标签后触发无效引用警告。

真实 SSE 时间线已确认，25 秒全部发生在 understanding 阶段，图谱、文本和图片检索并未执行。

## 修复内容

- 明确问候语直接走本地规则闲聊路由，不调用 7B 路由模型。
- CASUAL 路由直接使用规则槽位，不调用槽位抽取模型。
- pipeline 增加阶段回调，在上下文、理解、规划和检索前后发送真实事件。
- stream_ask 将同步 pipeline 放入后台线程，主生成器持续转发事件。
- A 端把 started 转换为页面可展示的 SESSION_CONTEXT 阶段。
- 闲聊答案跳过引用校验，并清理误生成的 E 标签。
- 闲聊提示词不再要求引用。
- 页面在定位阶段显示“正在获取当前位置”，请求发出后显示“正在连接小V”。

## 测试

- pytest -q src/kg_qa_v2：62 passed。
- A 端 Django 测试：6 passed。
- B 端语法检查通过。
- 真实 SSE：约 0.10 秒收到 started，约 0.14 秒完成闲聊理解，约 0.21 秒收到首个答案 token，约 0.30 秒完成。
- 真实同步闲聊返回 HTTP 200、空 evidence、空 citations、空 warnings。

## 结论

本次问题不是图谱检索慢，而是闲聊误走模型理解链路并且流式阶段被同步阻塞。修复后，明确闲聊已达到实时 SSE 预期；知识问答仍会保留实体对齐、图谱检索和引用校验流程。
