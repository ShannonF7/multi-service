# Stage 30 审计：实体候选宽召回与澄清门控

## 目标

修复“智能光学实验室”只召回418节点、漏掉420节点的问题，同时保持候选质量和同名节点澄清能力。

## 根因

原候选查询只要求节点名称、描述、标签或属性键值完整包含整句查询。

用户查询：

```
智能光学实验室
```

可以命中：

```
418智能光学实验室
```

但无法命中420节点，因为420节点的已发布知识分散在属性和来源证据中，例如：

```
智能光学
SMARTOptics实验室
光电仪器数字孪生及数据处理研究团队
```

这些文本没有连续包含完整字符串“智能光学实验室”。

## 修改内容

### 1. 多词候选召回

文件：

```
src/rag/service/graph_discovery_service.py
```

新增：

- 保留完整查询匹配。
- 对中文查询生成双字核心词。
- 在节点描述和同一条已发布属性/来源证据中进行多词联合匹配。
- 语义候选必须同时满足：
  - 节点名称至少包含一个核心词；
  - 同一条属性或来源证据至少包含两个核心词。
- 返回 `match_type`：
  - `contains`
  - `semantic_description`
  - `semantic_evidence`

这避免了仅因为“实验室”等通用词而召回大量无关节点。

### 2. 实体对齐澄清门控

文件：

```
src/kg_qa_v2/entity.py
```

新增两类直接澄清规则：

1. 名称候选与属性语义候选同时存在时，不调用Jev强行选择。
2. 同名但层级不同的候选必须澄清。

这样：

```
智能光学实验室
→ 418智能光学实验室
→ 420智能光学成像课题组
→ 用户确认
```

以及：

```
财务部
→ 行政楼·B座·一层
→ 行政楼·B座·二层
→ 用户确认
```
