# KG-QA v2 第 19 阶段审计：简单问题快速路由

## 1. 线上问题

知识问题“行知楼在哪里？”的线上计时显示：

- router_ms 约 26440 ms；
- slot_ms 约 885 ms；
- 请求在实体澄清前结束，没有进入答案首 token。

因此主要瓶颈是本地 7B Router，不是定位、图谱查询或答案生成。

## 2. 修复策略

router.py 增加保守的 fast rule：

- 仅处理长度不超过 80 的明确问法；
- 位置/事实关键词包括：哪里、在哪、位于、地址、附近、面积、多大、属于、上级、下级、组成、包含、有几个、哪些、路线、怎么去；
- 含比较、区别、差异、为什么、原因、详细介绍、分析、是否、能不能等复杂表达时不走快速规则；
- 生产默认本地决策客户端且没有测试 transport 时才启用；
- 注入的测试客户端、函数式客户端和托管 Jev 保持原有调用契约。

## 3. 输入输出

输入：用户问题、图片标记、当前会话上下文。  
输出：沿用 fallback_route 的标准 RouteDecision，不创建实体、不执行检索。

例如“校长办公室在哪里？”直接得到：
- route=KNOWLEDGE
- intent=LOCATION
- needs_graph=true
- source=fallback

后续槽位抽取、实体候选、图谱检索仍按原流程执行，快速路由只省略 7B Router 的一次调用。

## 4. 风险控制

快速规则不是全量分类器：

- 长问题和复杂语义仍交给模型；
- 关键词命中不代表实体一定存在；
- 实体对齐、领域过滤、已发布状态校验不变；
- 测试 transport 不被绕过，保证适配器测试仍能验证模型调用。
