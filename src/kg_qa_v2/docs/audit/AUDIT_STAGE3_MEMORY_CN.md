# QA v2 第三阶段中文代码审计：四层记忆与 Context Resolver

## 实现范围

本阶段只实现四层记忆的数据契约和读取裁剪逻辑，没有接入 Redis、PostgreSQL、pgvector，也没有修改现有会话存储。

## 输入输出

- 输入：问题、当前领域、session、user、实时位置、图片标记，以及是否需要长期记忆。
- 会话读取输出：实体状态和会话摘要。
- 长期记忆读取输出：按用户、领域和查询过滤后的长期语义记忆。
- `to_snapshot` 输出：仅供问题理解使用的精简 `ContextSnapshot`。

## 逻辑审计

1. `WorkingMemory` 只保存本轮请求状态，不跨轮复用。
2. `EntityState` 保存当前实体、最近实体和待确认候选，解决连续追问和代词指代。
3. `SessionSummary` 保存摘要和版本，不把原始消息自动塞给模型。
4. 长期记忆默认不读取，必须显式传入 `need_long_term=true`。
5. 长期记忆按 `domain_id` 二次过滤，防止不同领域污染。
6. `ContextSnapshot` 不包含原始 `messages` 字段，保证后续 Prompt 只接收裁剪后的上下文。

## 已验证行为

- 会话数据可以恢复当前实体、最近实体、待确认候选和摘要。
- 原始历史消息不会进入问题理解上下文。
- 长期记忆不请求时不会访问长期存储。
- 请求长期记忆时会过滤其他领域数据。
