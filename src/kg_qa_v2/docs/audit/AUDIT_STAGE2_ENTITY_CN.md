# QA v2 第二阶段中文代码审计：候选搜索与实体对齐

## 实现范围

本阶段只新增候选搜索和实体对齐模块，没有修改现有 `src/kg_qa`、图谱服务、数据库或 API。

## 输入输出

- 候选搜索输入：自然语言 mention、当前领域、当前节点、定位节点、数量上限。
- 候选搜索输出：当前领域内的候选节点列表，并保留层级路径、别名、分数和距离。
- 实体对齐输入：mention、候选列表、问题文本和上下文。
- 实体对齐输出：`LINKED`、`AMBIGUOUS` 或 `UNRESOLVED`，并记录置信度、理由和候选。

## 逻辑审计

1. 候选网关强制接收 `domain_id`，并强制传递 `published_only=true`。
2. 候选搜索不负责做最终身份判断，避免把召回结果当成用户真实指代。
3. 唯一候选只有在分数达到 0.92 时才自动链接；唯一精确名称或别名匹配可直接链接。
4. 多候选默认进入 `AMBIGUOUS`，不能因为第一个候选分数略高就强行选择。
5. Jev 只能从候选 node_id 中选择，返回不存在的 ID 或低置信度会回到保守结果。
6. 当前节点和候选层级冲突时，不自动链接。

## 已验证行为

- 候选搜索会携带当前领域和已发布过滤条件。
- 两个同名“财务部”不会自动选第一个。
- 明确别名“财务室”可以映射到唯一“财务部”。
- Jev 可以在有限候选中选择，但不能创建候选或跨领域选择。
- Jev 返回未知节点时不会污染实体对齐结果。
