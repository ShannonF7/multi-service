# 代码审计记录

## 审计范围

本次审计覆盖 src/reasoning/ 下的逻辑形式、上下文解析、问题理解、推理计划、执行器和单元测试。

## 输入输出

- ConversationContextView.from_mapping：输入可选字典，输出只读会话视图；非法节点 ID 不会抛出未处理异常。
- resolve_context：输入问题和会话视图，输出独立问题、活动目标、来源类型及是否使用上下文。
- understand_question：输入问题、领域 ID、可选上下文和已链接目标，输出 LogicalQuery。
- build_reasoning_plan：输入 LogicalQuery，输出白名单动作组成的 ReasoningPlan。
- ReasoningExecutor.run：输入 LogicalQuery、QARequest 和 DomainContext，输出实体、图谱结果、检索结果、统一证据及告警；歧义和未解析状态在检索前返回。
- unresolved_position_answer：输入未找到名称，输出不暴露内部实现、且能引导用户补充条件的中文回复。

## 逻辑检查

- “我现在在哪里”优先识别为实时位置问题，不会抽取出“我现在”这样的伪节点。
- “它在哪里”等连续追问优先使用最近一轮目标。
- “二楼的”“第 2 个”等回答优先解析上一轮候选项。
- 问题中的上层、上上层等限定词保留在目标短语中，交给当前领域的实体链接器继续确认。
- 闲聊输出空计划，不访问知识库。
- 未找到时不向用户展示“实体”“强行拼接”等内部策略词，而是说明当前未查到并给出下一步补充方向。
- 实体解析成功后才把名称回填为节点 ID，并重新编译计划；歧义或完全未解析时不会查证据。
- 图谱、文本和图片均从当前领域参数进入现有服务，证据结果必须经过 fuse_evidence。

## 安全与副作用

- 推理核心无数据库写入、网络写入、模型调用和业务数据副作用。
- 执行器只调用现有只读实体、图谱、文本和图片检索接口。
- 推理动作使用固定白名单，非法动作会被立即拒绝。
- 图谱与证据计划都带 published_only。
- 路径、邻域、候选项和证据数量均有固定上限。
- 本阶段不执行自然语言到任意查询语句的直接拼接。

## 中文可维护性

- 公开类、函数和关键分支均有中文 docstring 或注释。
- 数据输入、输出和边界行为在本文件中有中文记录。
- 单元测试覆盖当前位置、代词、待选择项、层级限定词、闲聊、歧义、真实服务适配和有限多跳计划。

## 当前限制

- 目前只有规则型问题理解，不代表最终意图识别能力。
- 执行器已经接入 QAService 的答案编排；线上服务重载后由该路径处理知识问题。
- 规则推理动作暂时是执行计划中的保留动作，尚未实现独立规则库。
- SSE 仍由现有 kg_qa API 负责，新执行器通过阶段回调提供实体链接、计划、检索和证据融合轨迹。
